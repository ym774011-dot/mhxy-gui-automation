## 0. 背景与硬约束

- 现状 `zhuagui_in_battle`（ZGUI.py:1166-1168）读 `tp.战斗中`：
  ```python
  def zhuagui_in_battle(gateway=DEFAULT_GATEWAY, **kw):
      return _lua_call(gateway, '__out = tostring(tp.战斗中)') == "true"
  ```
  该字段在本服（卡通版胖子西游）**被用户明令禁用**作成功判据（恒空/不可信）。
- 待实测字段（全仓库业务代码**零命中**，本服是否存在未证实）：
  - `tp.战斗类.参战单位` / `tp.战斗类.敌方数量` / `tp.战斗类.背景显示`
  - `tp.战斗中`（已禁用，但仍作为**诊断**字段记录）、`tp.地图.地图名称`
- T6 目标：把"真战斗"判据接入链路，在 CALL 野鬼后防止重复点击 / 误判完成 / 误触传送。

## 1. 三个接入点分析

### 1.1 `zhuagui_click_ghost`（ZGUI.py:1050-1089）
- 作用：CALL `客户端:发送数据(0,3,6,标识,1)` 触发野鬼对话（等效点击野鬼）。
- 防护点：**CALL 前判"是否已在战斗/对话中"**。若此刻已在战斗（如上一只鬼的奖励动画未结束、或意外遭遇野怪），CALL 会落空或误操作。接入建议：CALL 前若新判据判定"在战斗中" → 等待/跳过本轮 CALL，而非盲目发包。
- 影响：纯防护，不改变成功路径。

### 1.2 `zhuagui_enter_battle`（ZGUI.py:1171-1235）★ 关键矛盾点
- 作用：一键进战主流程（CALL→点"送你回地府"→轮询任务栏确认完成）。
- ⚠ **本流程注释明确写道**（:1182-1185）：
  > 本版本点"送你回地府" = 直接秒杀 + 发放奖励，**不会进入战斗场景**。
  > 成功判据为任务栏"次数递增 或 清空"。
- **矛盾**：既然点"送你回地府"本就不进战斗，则"是否战斗中"判据在此链路**天然永远为 false**，无法用作成功判据。T6 的"战斗防护"在这里的真实防护对象必须澄清：
  - (a) 仅防"CALL 前已在别的战斗中导致 CALL 落空"？ → 同 1.1，归到 click_ghost 前；
  - (b) 还是抓鬼过程中存在**另一种**真战斗遭遇（地图野怪）需要防护？
  - 当前代码与注释不支持 (b)。**建议 team-lead / 用户明确** T6 要防护的"战斗"指什么，否则此接入点无意义。
- 防护点（若指 (a)）：点"送你回地府"**之前**用战斗判据确认不在战斗，避免在战斗态下强制点击导致异常。

### 1.3 `zhuagui_go_back_changan`（ZGUI.py:930-965）
- 作用：右键合成旗 → 点长安城红点回程接下一只。
- 防护点：**回程前确认不在战斗中**（战斗中强制传送会丢怪 / 掉线）；或回程途中检测到异常进入战斗则中止传送。
- 接入建议：函数开头插入"若在战斗则先等待/退出战斗再传送"，用新判据替代（也更稳于 `tp.战斗中`）。

## 2. 判据候选表

| 候选 | 来源字段 | 误报风险 | 漏报风险 | 备注 |
|---|---|---|---|---|
| A 参战单位非空 | `tp.战斗类.参战单位`（pairs>0） | 低（本服单角色单开，无友方战斗串扰） | 中（字段本服存在性**待 T4 证实**） | 首选单字段 |
| B 敌方数量>0 | `tp.战斗类.敌方数量` | 低 | 中（存在性待证） | 语义最直白 |
| C 背景显示==true | `tp.战斗类.背景显示` | 中（打开某些 UI 也可能置位） | 中 | 需 T4 看真实值语义 |
| **D 组合：参战单位非空 AND 地图名称≠安全城镇** | A + `tp.地图.地图名称` | **极低** | 低 | **推荐主判据** |
| ⛔ E `tp.战斗中` | 用户明令禁用 | — | — | **不采用**，仅作诊断采样 |

**推荐 D**：战斗逻辑上要求"有参战单位 **且** 不在安全城镇地图（长安城/建邺城/江南野外等）"。
- 漏报仅发生在 T4 证实 `tp.战斗类` 本服不存在时 —— 此时无判据可用，需回退到**现有任务栏次数判据**（即 `zhuagui_enter_battle` 现行逻辑），战斗防护退化为"无额外判据 + 现有超时复查"。

## 3. 与「禁用 tp.战斗中」约束的关系

- 用户禁用 `tp.战斗中` 作**成功判据**：本服该字段恒空/不可信，不能作为"完成"或"进战"信号。
- 但 T4 探针**仍记录其存在性与值**（仅诊断，落盘 `battle_probe_*.jsonl`），不写入任何业务判据。
- 本文所有候选判据（A/B/C/D）**均不依赖 `tp.战斗中`**，与用户约束一致。

---

## 4. 实施边界与待定项

1. **字段存在性 → 待 T4 真机采样定稿**：若 T4 证实本服无 `tp.战斗类`，T6 只能沿用现有"任务栏次数递增/清空"判据（见 2 节退路）。落地脚本应以 `tools/_battle_probe.py` 的 jsonl 为依据，不可臆测。
2. **关键澄清项（需 team-lead/用户）**：`zhuagui_enter_battle` 注释称点"送你回地府"不进战斗，故 T6 战斗防护的真实对象需先明确（见 1.2）。在澄清前，1.2 接入点标记为「待定」。
3. **零副作用原则**：所有接入点只在判据结果为"在战斗"时做**保护性等待/跳过/中止**，不引入任何新点击或发包，符合硬约束。
4. **本方案仅文档**：实际改 ZGUI.py 由后续 T6 任务执行，须基于本文 + T4 采样结论。

## 5. 与 T4-prep 其它交付物的关联

- `tools/_battle_probe.py`：产出 `test_data/battle_probe_YYYYMMDD_HHMMSS.jsonl`（SCHEMA_VERSION=1），逐行含 `fields`（存在性/类型/值/异常）+ `units`（参战单位明细）。本文第 2 节判据 A/B/C/D 与第 4 节待定项，均依赖该 jsonl 中字段的真实观测值。
- 建议 T4 执行时在**真战斗进行中**启动探针，并对照**非战斗态**（如长安城站街）各采一批，对比两组 `fields` 差异，即可直接填定判据阈值。
